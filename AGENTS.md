# Правила развития TeachEm

- Перед изменениями проверяйте Git. Сохраняйте существующую работу, не перезаписывайте чужие или незавершённые изменения. Каждую законченную доработку оформляйте отдельным коммитом; в отчёте указывайте его и команду git revert для отката.
- Развивайте существующие доменные модули постепенно, без полной переписи. Сохраняйте границы авторизации, пользователей, тьюторов, курсов, занятий и остальных модулей.
- Настройки бренда держите в packages/shared/src/brand.ts, логотип — в apps/web/components/brand/logo.tsx. Общие элементы интерфейса переиспользуйте.
- Отделяйте представление от бизнес-логики и доступа к данным. Модуль бренда содержит только публичные значения и не зависит от UI, БД или API.
- Переключатели функций вводите при необходимости для крупных функций; не добавляйте их для мелких визуальных изменений.
- Изменения БД оформляйте миграциями с сохранением данных. Перед разрушительными изменениями нужны резервная копия и проверяемый способ восстановления. Откат кода не восстанавливает данные.
- Проверяйте изменённый сценарий и связанные основные функции. В отчёте указывайте изменения, проверки, ограничения и способ отката.
- Не добавляйте продуктовые функции без конкретного задания. Избегайте лишних абстракций.
