# TeachEm

Платформа для тьюторов и учеников: независимый REST API на Go, Next.js App Router, PostgreSQL 16 и закрытое S3-хранилище. Русский интерфейс, KZT, ручная оплата и доступ на выбранный срок курса. Frontend остаётся на TypeScript; Node.js и Prisma для работы сервера больше не нужны.

## Что проверено при переносе на Go

- Модульные тесты Go и HTTP-интеграционные сценарии всех доменов на отдельной PostgreSQL-базе, включая копию существующих данных.
- Совместимость старого и нового серверов в обе стороны: bcrypt-хеши, JWT и серверные сессии.
- Чистая установка, повторный seed без изменения существующего владельца и настроек.
- Загрузка и скачивание через настоящий MinIO в отдельном временном bucket.
- Production-сборки Docker для API и Next.js.
- Рабочий Compose с Go API, вход прежнего суперадминистратора, панель пользователей, профиль, каталог, теги и редактор курса в браузере. Все 20 таблиц совпали до и после переключения и повторного запуска; сессия пережила перезапуск.

Карта API, устройство переноса и откат: [перенос на Go](docs/go-migration.md). Проверки изолированной среды не заменяют проверку конкретного развёртывания.

## Запуск сайта

Нужен работающий Docker Desktop / Docker Engine с Compose v2. Go, Node.js и pnpm на компьютере для этого варианта не требуются.

1. При первой установке скопируйте корневой `.env.example` в `.env`. Существующий `.env` сохраните.
2. Укажите пароли PostgreSQL и MinIO, два разных случайных JWT-секрета длиной минимум 32 символа и данные первоначального владельца `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Пароль владельца — минимум 12 символов и максимум 72 байта. Seed использует эти данные только при отсутствии SUPERADMIN; существующий логин и пароль не перезаписывает.
3. Из корня проекта выполните:

```sh
docker compose up -d --build --wait
```

На Windows можно использовать помощник, который также проверит готовность и откроет страницу входа:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

Compose запускает PostgreSQL и MinIO, применяет SQL-миграции Go-командой, выполняет seed и запускает Go API, frontend и Nginx. После обновления исходников снова выполните команду с `--build`, чтобы увидеть новую версию.

| Сервис | Адрес |
|---|---|
| Вход | http://localhost:8080/login |
| Каталог | http://localhost:8080/catalog |
| Панель пользователей SUPERADMIN | http://localhost:8080/admin/users |
| Swagger | http://localhost:8080/api/docs |
| OpenAPI JSON | http://localhost:8080/api/openapi.json |
| Готовность API и хранилища | http://localhost:8080/health/ready |
| MinIO Console | http://localhost:9001 |

После первой установки войдите владельцем и заполните **Настройки → Реквизиты платформы**. До этого новые платежи создать нельзя. Начальная комиссия — 10%; повторный seed не меняет настройки.

```sh
docker compose logs --tail 80 api
docker compose stop
docker compose start
```

`stop` и `down` сохраняют БД и файлы в volumes. Не используйте `down -v` для остановки работающей платформы.

MinIO и `mc` собираются из закреплённых официальных исходников; первая сборка требует интернета. Версии: [MinIO](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z), [mc](https://github.com/minio/mc/releases/tag/RELEASE.2025-08-13T08-35-41Z). Их лицензия AGPL сохраняется.

## Разработка без контейнера API

Нужны Go 1.25+ (Docker и CI используют 1.27.1), Node.js 22+ и pnpm 10.17.1. PostgreSQL и MinIO можно оставить в Docker.

```sh
corepack enable
corepack prepare pnpm@10.17.1 --activate
pnpm install --frozen-lockfile
docker compose up -d postgres minio storage-init
docker compose run --rm migrate
docker compose run --rm seed
```

На Windows в первом терминале запустите API:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-api.ps1
```

Помощник читает корневой `.env`, подключается к локальным PostgreSQL/MinIO и использует `http://localhost:3000` как origin. Во втором терминале:

```sh
pnpm dev
```

Откройте http://localhost:3000. Next.js перенаправляет `/api/*` на Go API по адресу `http://localhost:4000`; отдельный Nginx для разработки не нужен. Если загрузка напрямую в MinIO блокируется браузером, задайте `PUBLIC_ORIGIN=http://localhost:3000` в окружении команды Compose и пересоздайте `minio`: его CORS должен соответствовать адресу сайта. Для обычного запуска через gateway верните origin 8080.

Go API можно запускать независимо от pnpm и frontend. Передайте переменные из `apps/api-go/.env.example` в окружение процесса, затем из корня:

```sh
go -C apps/api-go run ./cmd/server migrate
go -C apps/api-go run ./cmd/server seed
go -C apps/api-go run ./cmd/server
```

Go автоматически **не читает** файлы `.env`. Для `migrate` требуется `DATABASE_URL`; для первоначального `seed` также нужны данные владельца. Для сервера нужны JWT-, origin- и S3-настройки из примера. Значения Compose с именами узлов `postgres` и `minio` при запуске вне Docker заменяются на `localhost`. `pnpm dev:api`, `pnpm db:migrate` и `pnpm db:seed` — сокращения тех же Go-команд; они тоже используют уже заданное окружение.

## Миграции и сохранность данных

SQL находится в `apps/api-go/internal/migrate/sql` и включается в бинарный файл. Четыре исходные миграции перенесены без изменения схемы; журнал `_prisma_migrations` и его контрольные суммы сохранены. Применённые изменения не запускаются повторно. Prisma CLI и генерация Prisma Client больше не используются.

Новую схему оформляйте **новым** файлом `YYYYMMDDNNNN_description.sql`. Не редактируйте применённые миграции. Проверяйте чистую установку и обновление копии текущей БД; сохраняйте свежую резервную копию перед изменением схемы. Runner блокирует одновременный запуск миграций и применяет каждый SQL-файл вместе с записью журнала в транзакции.

Перенос на Go не меняет схему, аккаунты, покупки или ключи файлов. Обычный откат переключения сервера использует ту же БД и MinIO, без восстановления старого дампа. Порядок описан в [документе переноса](docs/go-migration.md).

## Проверки

```sh
go -C apps/api-go vet ./...
pnpm test
pnpm lint
pnpm typecheck
pnpm api:generate
pnpm build
```

`pnpm test` запускает Go-тесты; HTTP-проверки БД и реального S3 пропускаются без соответствующего окружения. Для полного HTTP-набора создайте отдельную PostgreSQL-базу, имя которой содержит `test`. Передайте её URL одновременно как `DATABASE_URL` для миграций и `TEACHEM_TEST_DATABASE_URL` для тестов:

```sh
go -C apps/api-go run ./cmd/server migrate
pnpm test:e2e
```

`scripts/test-go.cjs` требует тестовую БД и запускает пакеты последовательно (`-p 1`): тесты изменяют тестового владельца и создают учебные данные. Не используйте рабочую БД. Отдельная восстановленная копия подходит; она должна быть изолирована от рабочего приложения.

Для настоящего S3 задайте `TEACHEM_TEST_S3_ENDPOINT=http://localhost:9000`, `TEACHEM_TEST_S3_ACCESS_KEY` и `TEACHEM_TEST_S3_SECRET_KEY`, затем запустите тот же набор. Проверка создаёт собственный временный bucket и удаляет его после завершения. Без этих переменных HTTP-тесты используют адаптер хранилища в памяти; реальный S3-тест будет явно пропущен.

CI проверяет Go vet, HTTP-тесты на PostgreSQL, lint, TypeScript, актуальность сгенерированного клиента и сборки. S3-интеграция запускается отдельно при наличии MinIO. Контракт хранится в `apps/api-go/contracts/openapi.json`; команда `pnpm api:generate` обновляет только `apps/web/lib/api-client/schema.ts`. Контракт нужно менять вместе с реализацией; генерация не извлекает маршруты автоматически из Go.

## Архитектура и новые доработки

| Каталог | Ответственность |
|---|---|
| `apps/api-go/cmd/server` | Сборка приложения, команды serve/migrate/seed/healthcheck |
| `apps/api-go/internal/core` | HTTP, ошибки, CSRF, права, настройки, PostgreSQL и транзакции |
| `apps/api-go/internal/accounts` | Вход, сессии, личный профиль, тьюторы, управление пользователями |
| `apps/api-go/internal/learning` | Каталог, курсы, записи, материалы, занятия, тесты и ответы |
| `apps/api-go/internal/commerce` | Загрузки файлов, платежи, начисления, выплаты, настройки и аудит |
| `apps/api-go/internal/storage` | Адаптер MinIO/S3 |
| `apps/api-go/internal/migrate` | SQL-миграции и начальные данные |
| `apps/web` | Next.js, общий UI, формы и REST-клиент |
| `packages/shared` | Публичные настройки бренда, роли и правила представления |

Это модульный монолит: транзакция оплаты объединяет подтверждение, доступ, начисление и аудит. Backend работает независимо от frontend и не требует Node.js. Фронтенд не обращается к БД; прежний сервер TypeScript доступен только в истории Git.

Перед доработкой проверьте Git и сохраните существующие изменения. Добавляйте обработчик и проверку входных данных в соответствующий модуль; SQL держите в его репозитории, правила доступа проверяйте на сервере. Для межмодульных сценариев используйте существующие проверки курса и транзакции. Обновляйте контракт API и клиент, переиспользуйте общие UI-компоненты. Проверяйте изменённый сценарий, отказ в доступе и связанные функции; завершайте отдельным коммитом с инструкцией `git revert`. Правила проекта: [AGENTS.md](AGENTS.md).

## Сохраняемые правила платформы

- Суммы — целые тиыны, валюта KZT. Цена, длительность и комиссия фиксируются при создании платежа. Комиссия округляется вниз до тиына.
- Доступ продлевается от `max(сейчас, текущий срок)` на `Payment.durationDays × 24 часа`. Изменение курса не меняет старые покупки. Для исходных курсов и платежей сохранён срок 30 дней.
- Один незавершённый платёж на запись; повторное подтверждение не начисляет деньги повторно.
- Архив курса закрывает новые покупки, сохраняя уже оплаченный доступ.
- Опубликованные тесты неизменяемы: для новой версии создаётся копия. Баллы начисляются за точный набор ответов, без частичных и отрицательных баллов.
- Материалы: PDF, DOCX, PPTX, JPEG, PNG, WebP до 20 МиБ. Обложка: JPEG, PNG, WebP до 5 МиБ. Размер, MIME и содержимое проверяются сервером.
- Временная загрузка действует 5 минут. После проверки файл получает отдельный постоянный ключ; ссылка скачивания действует 60 секунд. Полноценного антивируса нет.
- JWT — только в httpOnly cookies; сервер проверяет сессию, роль и блокировку. Повторное использование старого refresh отзывает сессию.
- Meet-ссылка выдаётся отдельным защищённым запросом; отменённое занятие недоступно.
- У списков есть пагинация; ошибки имеют общий формат и `X-Request-ID`.

## Production и границы MVP

Для внешнего размещения настройте HTTPS, `NODE_ENV=production`, `COOKIE_SECURE=true`, точные `PUBLIC_ORIGIN` / `CORS_ORIGINS`, публичный HTTPS endpoint S3 и CORS. Используйте отдельные credentials нужного bucket. Включайте `TRUST_PROXY=true` только за своим reverse proxy; не открывайте API напрямую в обход него.

Миграции и seed — отдельные шаги перед запуском API. Настройте резервное копирование PostgreSQL и bucket. Swagger при необходимости закройте на proxy. Для внешнего Next.js направьте `API_INTERNAL_URL` на сервер: rewrite сохраняет запросы браузера к общему origin. Не помещайте секреты в `NEXT_PUBLIC_*`.

Оплата и Meet остаются ручными. Автоматический эквайринг, возвраты, доставка уведомлений, восстановление пароля и подтверждение email не реализованы. Планировщика и активных фоновых задач нет.
