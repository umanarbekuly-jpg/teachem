# Точка роста

MVP платформы для тьюторов и учеников: независимые NestJS REST API и Next.js App Router, PostgreSQL/Prisma, закрытое S3-хранилище. Русский интерфейс, KZT, ручная оплата и доступ на 30 дней.

## Результаты проверки этой версии

- Сборка API и production-сборка Next.js: пройдены.
- TypeScript и ESLint: без ошибок.
- Jest: 26 unit/security-тестов и 6 HTTP-интеграционных сценариев пройдены.
- Обе миграции применены к чистой PostgreSQL 18.4. В Compose и CI закреплена PostgreSQL 16; именно этот контейнер локально не запускался.
- Загрузка и скачивание файлов проверены через S3-совместимый эмулятор, включая запрет чужого доступа и защиту от перезаписи готового объекта.
- В браузере проверены вход тьютора, список и страница курса, сохранение учебной ссылки, адаптивная главная страница.
- Docker отсутствовал в среде проверки: полный Compose и сборка образов MinIO не выполнялись. Production-сборка Next.js на Windows потребовала повторной попытки создания каталогов из-за локальной ошибки `EPERM`; сам исходный код приложения не зависит от этого обхода.

Это локальный MVP для дальнейшего развёртывания. Внешние платёжные и видеоинтеграции пока ручные.

## Быстрый запуск

Нужен Docker Desktop / Docker Engine с Compose v2. Для запуска исходников без контейнеров — Node.js 22+ и pnpm 10.17.1.

1. Скопируйте корневой `.env.example` в `.env`.
2. Замените пароли PostgreSQL, MinIO, администратора и оба JWT-секрета. JWT-секреты — разные случайные строки минимум 32 символа. Пароль администратора — 12–72 байта. Email администратора задаётся в `ADMIN_EMAIL`.
3. Из корня проекта выполните:

```sh
docker compose up --build
```

Compose дождётся БД, применит миграции, создаст закрытый bucket и администратора, затем запустит API, frontend и reverse proxy.

MinIO и `mc` собираются из закреплённых официальных исходников: прежние публичные образы недоступны. Первый запуск требует интернета и занимает больше времени. Источники: [MinIO release](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z), [mc release](https://github.com/minio/mc/releases/tag/RELEASE.2025-08-13T08-35-41Z). Обратите внимание на лицензию AGPL у этих инфраструктурных компонентов при распространении сборок.

| Сервис | Адрес |
|---|---|
| Сайт | http://localhost:8080 |
| Swagger | http://localhost:8080/api/docs |
| OpenAPI JSON | http://localhost:8080/api/openapi.json |
| Готовность API | http://localhost:8080/health/ready |
| MinIO Console | http://localhost:9001 |

Войдите администратором → **Настройки** → укажите реквизиты платформы. До этого создание платежа запрещено. Начальная комиссия — 10%. Seed не перезаписывает существующий пароль или настройки.

```sh
docker compose run --rm migrate
docker compose run --rm seed
docker compose down
```

`docker compose down` сохраняет БД и файлы в volumes. Не добавляйте `-v`, если данные нужно сохранить.

## Локальная разработка

```sh
corepack enable
corepack prepare pnpm@10.17.1 --activate
pnpm install --frozen-lockfile
pnpm db:generate
pnpm --filter @tutor/shared build
```

Скопируйте примеры `.env` обоих приложений. Поднимите PostgreSQL и MinIO через `docker compose up -d postgres minio storage-init`, примените миграции и seed из локального процесса:

```sh
pnpm db:migrate
pnpm db:seed
pnpm dev
```

API работает на 4000, web на 3000. Для одного домена нужен reverse proxy: приведённый `infra/nginx/default.conf` направляет `/api/` на API, остальные пути — на web. Для разработки можно использовать Nginx с upstream `host.docker.internal:4000` и `host.docker.internal:3000`; `PUBLIC_ORIGIN` должен совпадать с фактическим адресом в браузере. Прямой запуск web на 3000 без прокси не обслуживает `/api/v1`.

При изменении Prisma-схемы создавайте миграцию через `pnpm --filter @tutor/api exec prisma migrate dev --name change_name`. Не используйте ручные изменения схемы или `db push` для развёрнутой БД.

## Проверки

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm api:generate
pnpm build
```

Для e2e задайте `DATABASE_URL` отдельной **тестовой** PostgreSQL-базы, содержащей `test` в имени URL, и остальные API-переменные окружения; примените миграции, затем:

```sh
pnpm test:e2e
```

Сквозная проверка загрузки файлов на работающем локальном стенде: `node scripts/storage-smoke.cjs`. Скрипт создаёт синтетические аккаунты `@example.test`, проверяет presigned POST, завершение загрузки, скачивание, чужой доступ, MIME, размер и защиту от перезаписи. Запускайте только на тестовом стенде.

E2E создают уникальных тестовых пользователей и учебные записи. Они используют настоящий PostgreSQL и заменяют только адаптер хранилища. Проверка самого S3 выполняется отдельным сценарием вручную: загрузка → подтверждение → скачивание с активным доступом → отказ другому ученику. Не запускайте e2e на рабочей базе.

CI выполняет lint, typecheck, unit, e2e с PostgreSQL, проверку актуальности OpenAPI-клиента и сборку. `apps/api/openapi.json` и `apps/web/lib/api-client/schema.ts` включены в репозиторий; меняйте их только генерацией.

## Проверка по этапам

| Этап | Что проверить | Переменные |
|---|---|---|
| 0 — инфраструктура | Чистый запуск Compose, health ready, повторный seed | `DATABASE_URL`, `S3_*`, пароли Compose |
| 1 — auth и каталог | Регистрация ученика/тьютора, вход/выход, публичный профиль, поиск, приватный черновик | `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `PUBLIC_ORIGIN`, `CORS_ORIGINS`, `COOKIE_SECURE` |
| 2 — материалы и запись | Создать курс, загрузить PDF/Office/изображение, записаться; неоплаченному ученику файл недоступен | `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT`, `S3_BUCKET`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` |
| 3 — финансы | Заполнить реквизиты, отправить чек, подтвердить/отклонить, продлить, отметить выплату, проверить аудит | `ADMIN_EMAIL`, `ADMIN_PASSWORD` для seed; комиссия и реквизиты в БД |
| 4 — тесты | Создать и опубликовать тест, пройти учеником, проверить баллы и результаты тьютора | Новых нет |
| 5 — занятия | Создать Meet-встречу, открыть из расписания, отменить; просроченный доступ закрыт | Новых нет |

Unit-тесты покрывают округление комиссии, границы доступа и продление, точный набор ответов, сигнатуры файлов, Meet URL, скрытие ответов, replay refresh и повторное подтверждение. E2E покрывают HTTP/RBAC/IDOR/CSRF, публикацию, ручную оплату, конкурентное подтверждение, тесты и расписание.

## Архитектура

- `apps/api/src/modules` — доменные модули с DTO, контроллерами, сервисами и репозиториями. Записывать чужие таблицы из доменного репозитория нельзя; операции между доменами проходят через сервисы.
- `infrastructure/database` — Prisma и сериализуемые транзакции с ограниченным повтором при конфликтах.
- `infrastructure/storage` — S3-адаптер. `modules/materials/files.module.ts` отвечает за жизненный цикл загрузки.
- `modules/payments/payments.provider.ts` — ручной провайдер реквизитов; подтверждение и доступ принадлежат доменным сервисам.
- `modules/sessions` — `VideoProvider` и `ManualMeetLink`.
- `infrastructure/notifications` — заглушка уведомлений и контракт будущих задач. Redis/BullMQ не запускаются.
- `apps/web` — только REST-запросы, React Query, React Hook Form/Zod и UI-компоненты на Tailwind/Radix в структуре shadcn/ui.
- `packages/shared` — роли и константы; не экспортирует Prisma или серверные секреты.

Модульный монолит использует общую БД и атомарную транзакцию для оплаты, доступа, начисления и аудита. Для реального выделения микросервисов понадобятся outbox, идемпотентные потребители и согласование распределённых операций; автоматическое разделение без этих изменений не предполагается.

## Правила MVP

- Суммы — целые тиыны, `KZT`. Цена курса и процент комиссии фиксируются при создании платежа. Комиссия округляется вниз до тиына.
- Один незавершённый платёж на запись. Подтверждение идемпотентно; начисление уникально по платежу.
- Доступ: `max(сейчас, текущий срок) + 30 × 24 часа`. Проверяется на каждом запросе, cron не нужен.
- Архив курса закрывает новые оплаты, но сохраняет уже оплаченный доступ.
- Опубликованные тесты неизменяемы. Создайте копию для новой версии. Частичных и отрицательных баллов нет.
- Материалы: PDF, DOCX, PPTX, JPEG, PNG, WebP, до 20 МиБ. SVG и HTML не разрешены. Чеки: PDF/изображения. Фото: изображения.
- Временная загрузка действует 5 минут; API проверяет размер, MIME и сигнатуру. Готовый объект получает новый ключ, поэтому временная ссылка не может его перезаписать. Ссылки скачивания действуют 60 секунд.
- Office-файлы проверяются по структуре контейнера и наличию VBA, но полноценный антивирус не включён. Для production с недоверенными загрузками можно добавить сканер в адаптер проверки.
- Токены JWT хранятся только в httpOnly cookies. Access — 15 минут, refresh — до 30 дней. Проверяются серверная сессия и блокировка. При повторном использовании старого refresh сессия отзывается.
- Ссылки Meet выдаются отдельным защищённым запросом. Отменённое занятие недоступно.
- Все списки имеют пагинацию. В API единый формат ошибки и `X-Request-ID`.

## Production

Docker Compose предназначен для локального запуска. Перед production: настройте HTTPS, `NODE_ENV=production`, `COOKIE_SECURE=true`, точные `PUBLIC_ORIGIN`/`CORS_ORIGINS`, публичный HTTPS endpoint S3 с CORS и отдельные credentials с правами только на нужный bucket. Не публикуйте порт API напрямую: приложение доверяет одному reverse proxy для IP-адреса клиента.

Для Next.js на Vercel настройте rewrite `/api/*` на API и сохраните общий origin; самостоятельный backend размещается отдельно. `API_INTERNAL_URL` зарезервирован для будущих серверных REST-запросов, текущий интерфейс получает данные в браузере. Не задавайте секреты через `NEXT_PUBLIC_*`.

Миграции и seed запускаются отдельным deploy-шагом до API. Настройте резервное копирование PostgreSQL и bucket. Для production Swagger следует закрыть на уровне proxy. Готовые Dockerfile включены.

Не включены: автоматический эквайринг, возвраты, групповые выплаты, автоматическое создание Meet, доставка уведомлений, восстановление пароля и подтверждение email. Это явные границы MVP, а не активные интеграции.
