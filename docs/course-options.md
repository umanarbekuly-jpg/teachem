# Курсы: обложка, срок, предмет и хештеги

## Где открыть

- Тьютор: `/tutor/courses/new`, редактирование — «О курсе» в своём курсе.
- Суперадмин: `/admin/courses`, включая черновики и архив; редактирование `/admin/courses/{id}`.
- Каталог: `/catalog`; фильтр тега — `?tag=код`, сочетается с предметом, поиском и ценой. Кнопка «Сбросить тег» сохраняет остальные условия.

Запуск из папки проекта: `powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1`. Docker Desktop должен быть открыт. Скрипт пересобирает приложения и применяет миграции, не сбрасывая данные и пароль суперадмина. Адрес: http://localhost:8080/.

## Данные и границы модулей

Историческая миграция `202610220001_course_options` добавила `Course.durationDays` (30 для старых курсов), `tags` (пустой массив), необязательную ссылку на `FileAsset` и `Payment.durationDays` (30 для всех старых платежей, в том числе ожидающих проверки). Старые цены, уровни и даты доступа не изменяются. Сейчас SQL хранится в `apps/api-go/internal/migrate/sql/202610220001_course_options.sql`; Go-runner использует прежний журнал `_prisma_migrations` и не применяет миграцию повторно.

Имя поля `monthlyPriceMinor` сохранено для совместимости: теперь оно означает полную цену за `durationDays`, в тиынах. Сумма и срок копируются в платёж при его создании. Повторное получение реквизитов возвращает незавершённый платёж с первоначальными условиями. Подтверждение оплаты продлевает доступ на срок из платежа, а не из текущего курса.

Предмет остаётся существующей строкой `Course.subject`. Общий список интерфейса находится в shared; Go API сохраняет те же девять названий и порядок. Новые названия очищаются от лишних пробелов; повторное название использует существующее написание без учёта регистра. Чтение названия и сохранение курса идут в Serializable-транзакции с повтором конфликтов, чтобы одновременные запросы не порождали разные написания. Каталог получает варианты из опубликованных курсов и стандартного списка.

Хештеги хранятся в нижнем регистре без `#`; отображение добавляет один `#`. API проверяет формат, количество и уникальность; база дополнительно ограничивает количество тремя. Поиск по полному тегу работает с `#` и без него. На массиве тегов есть GIN-индекс.

Обложки используют существующий процесс `files/uploads → S3 → complete`, назначение `course_cover`, лимит 5 МиБ. Go-сервер сверяет размер, MIME и сигнатуру, проверяет декодирование JPEG/PNG/WebP; ограничение — 40 млн пикселей. Проверенные байты копируются под новый ключ, чтобы прежняя ссылка загрузки не могла подменить обложку. При удалении обложки из курса файл не уничтожается: это сохраняет возможность восстановления. Готовые, но больше не используемые файлы пока не очищаются автоматически.

Переиспользуемые UI-компоненты: `course-editor.tsx` и `course-presentation.tsx`. Правила тегов, размеров и склонения дней — `packages/shared/src/course.ts`. Уровень остаётся в базе для обратимости, но не требуется и нигде не показывается в интерфейсе курса.

Серверные правила курса находятся в `apps/api-go/internal/learning`: `courses.go`, `courses_validation.go` и `courses_repository.go`. Процесс загрузки — в `internal/commerce/files.go`, S3-адаптер — в `internal/storage`. Изменение срока доступа использует сохранённые условия платежа в commerce, а проверка доступа к материалам переиспользуется из learning.

## Проверка

`pnpm test`, `pnpm test:e2e`, `pnpm typecheck`, `pnpm lint`, Docker-сборка. HTTP-тесты требуют `TEACHEM_TEST_DATABASE_URL` отдельной PostgreSQL-базы с `test` в имени и уже применённые миграции; на пользовательской базе их запускать нельзя.

Текущий Go-набор `apps/api-go/internal/learning/integration_test.go` проверяет создание курса с обложкой, своим предметом, сроком 45 дней и тремя тегами, повторное чтение и редактирование, фильтры, отсутствие обязательного уровня, отказ в чужом доступе и неизменность условий платежа после смены срока курса. Он также проверяет материалы, занятия, тесты, попытки и сохранение данных после перезапуска приложения. Модульные проверки ограничивают теги и параметры курса. `internal/commerce/integration_test.go` проверяет содержимое файлов, постоянные ключи и конкурентное подтверждение платежа. Эти наборы прошли на изолированном PostgreSQL; HTTP-слой использует хранилище в памяти. Настоящий MinIO отдельно проверен через `internal/storage/s3_test.go` в собственном временном bucket. Настройка окружения и ограничения: [README](../README.md#проверки).

### Историческая проверка интерфейса до переноса на Go

Проверено 23 октября 2026: 26 модульных и 22 интеграционных теста прошли; типы, lint и Docker-сборки API/Web успешны. В браузере создан и опубликован временный курс: собственный предмет «Вайбкодинг», обложка через реальное S3, 45 дней, 3 тега. Проверены повторное редактирование после перезагрузки, удаление и повторная загрузка обложки, быстрые сроки, ошибки тегов, поиск и сочетание фильтров, сброс тега и страница курса. На экране шириной 390 px у каталога и страницы курса нет горизонтального переполнения. Временный аккаунт, курсы и файлы удалены после проверки.

До и после миграции, а также после удаления тестовых данных сравнены исходные курсы (ID, предмет, уровень, цена), платежи (ID, сумма, статус) и записи (ID, начало и окончание доступа): совпадают. У исходных курсов проверены новые значения по умолчанию.

## Откат переноса сервера

При возврате Go → предыдущий TypeScript backend данные курса и условия покупок сохраняются: схема не менялась. Откатывается только коммит переключения запуска по [инструкции переноса](go-migration.md#откат-переключения-на-go), без восстановления старой базы.

### Исторический откат самой функции параметров курса

Следующие сведения относятся к добавлению параметров курса в октябре 2026, а не к переносу на Go. После миграции старые серверные коммиты нельзя отменять механически: код расположен в другом модуле; нужна отдельная доработка с сохранением условий покупок.

Коммиты: `8f2fc93` — сервер, миграция, контракты API и тесты; `9f613e2` — редактор, каталог и отображение курса. Изменения отменяют новым коммитом `git revert <hash>`, без `reset --hard` и без удаления томов Docker. После отката пересобрать приложения скриптом запуска. Перед откатом учитывать ограничения ниже.

Для отключения нового редактора можно откатить только UI-коммит, оставив сервер и дополнительные столбцы базы. Старый интерфейс снова показывает фиксированные 30 дней, поэтому при существующих курсах с другим сроком на время такого отката необходимо остановить новые покупки или исправить отображение отдельным коммитом.

**Не возвращать сервер с жёсткими 30 днями в работу, пока есть платежи с другим сохранённым сроком:** старый код обработает их неправильно. Для полной отмены сначала остановить API и запись данных, сохранить свежую резервную копию, проверить незавершённые платежи и выбрать согласованную версию кода и данных. При наличии новых покупок предпочтительно исправление вперёд с сохранением снимков условий.

До обновления локальной базы сохранена копия вне Git: `../../work/backups/teachem-before-courses-20261022.dump`. Восстановление проверяется сначала в новой базе через `pg_restore`, затем сверяются данные и переключается `DATABASE_URL`. Возврат старой копии теряет изменения после её создания, поэтому его нельзя выполнять автоматически. Откат Git сам по себе не восстанавливает базу и S3. Дополнительные столбцы, файлы и старые уровни при обычном откате не удалять.
