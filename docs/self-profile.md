# Личный профиль TeachEm

Откройте http://localhost:8080/login, войдите и нажмите блок аккаунта в меню кабинета. Адреса: `/student/profile`, `/tutor/profile`, `/admin/profile`. На телефоне блок аккаунта находится под горизонтальным меню. Ссылка смены пароля из шапки удалена.

Общий компонент показывает имя, фамилию, логин/email и роль. «Изменить данные» открывает форму; «Отмена» отбрасывает ввод. После сохранения обновляется общий кеш аккаунта, включая имя и инициалы. Профессиональные данные тьютора остаются отдельной формой на той же странице.

## Сервер и безопасность

Общая форма frontend сохранена для всех ролей. Серверная реализация находится в `apps/api-go/internal/accounts/users.go` и `auth.go`, проверки входных данных — в `validation.go`; отдельная система аккаунтов при переносе не создавалась.

- PATCH `/api/v1/users/me` определяет пользователя по сессии. Разрешены только name, surname, email и currentPassword; дополнительные поля отклоняются. Роль, статус, ID и чужие аккаунты не редактируются.
- Email приводится к нижнему регистру и проверяется сервером. Уникальность обеспечивается существующим ограничением базы; конфликт возвращает ошибку поля. Только SUPERADMIN может использовать специальный логин `supadmin@teachem`.
- Для изменения адреса нужен текущий пароль. Новый адрес сразу становится логином, emailVerifiedAt сбрасывается. Отправка писем подтверждения в проекте пока не реализована. Смена почты не завершает сессии.
- Смена пароля использует существующий POST `/api/v1/auth/change-password`: проверка текущего пароля, безопасное хеширование, отзыв всех сессий, затем вход заново. Общая форма также используется отдельной обязательной страницей смены временного пароля.
- Условное обновление и транзакция не позволяют применить результат проверки старого пароля после параллельного изменения версии авторизации или email. Пароли не возвращаются в ответах и не записываются в журнал.

## Проверки

Текущий набор `apps/api-go/internal/accounts/http_test.go` проверяет HTTP-авторизацию и профиль для всех ролей, нормализацию данных, занятый email, неверный текущий пароль, специальный логин, вход после смены почты и пароля, отзыв сессий/refresh, обязательную смену временного пароля и запрет привилегированных полей. Модульные тесты отдельно проверяют валидацию, bcrypt/JWT и отсутствие секретов в ответе. Go-набор прошёл на изолированном PostgreSQL.

Для запуска используйте `pnpm test:e2e` с `TEACHEM_TEST_DATABASE_URL` отдельной базы, содержащей `test` в имени. Сначала примените миграции, задав `DATABASE_URL` на ту же тестовую базу. Настройка: [README](../README.md#проверки). Старый `self-profile.e2e.ts` доступен только в истории Git; его не нужно запускать для нового сервера.

### Историческая проверка интерфейса до переноса на Go

Проверено 24 октября 2026: 26 модульных и 28 HTTP-тестов, TypeScript, ESLint и production-сборки API/Next.js. В браузере проверены открытие профиля всех трёх ролей, отмена, сохранение имени и фамилии, немедленное обновление блока аккаунта, сохранность после перезагрузки, профессиональная форма тьютора, ошибки имени и мобильная ширина 390 px. Смена email и пароля с повторным входом проверена HTTP-тестами; отправка этих изменений через браузер не выполнялась. Временные браузерные аккаунты удалены; действующие аккаунты не изменялись.

## Запуск и откат

В Windows запустите `scripts/start-local.ps1` из PowerShell. Либо выполните `docker compose up -d --build --wait` из корня проекта. Данные хранятся в существующих volumes; `down -v` не использовать.

Для отката именно переноса на Go используйте [инструкцию переключения сервера](go-migration.md#откат-переключения-на-go): профиль остаётся доступен, текущая БД и хранилище сохраняются. Возврат старого дампа не требуется.

Исторический коммит функции профиля — `cc1810b` (`feat(profile): add shared self-service account profile`). Его отмена относится к самой функции, а не к языку сервера; после переноса нельзя слепо отменять прежние серверные пути. Если потребуется убрать профиль, оформите отдельное согласованное изменение Go и UI. Функция не добавляла миграций: используется уже существующее поле surname, исходное имя не разделяется. Откат интерфейса не отменяет изменения личных данных или пароля, сделанные пользователями; они при необходимости меняются через действующие защищённые сценарии.
